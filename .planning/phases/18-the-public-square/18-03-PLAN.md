# Phase 18-03: The frontend read path

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reader with no account, or with an account that holds no slice here, sees the real conversation at a public place instead of a wall.

**Architecture:** Two new hooks, `usePublicFeed` and `usePublicThread`, call 18-02's RPCs and return the same `PostWithAuthor` / `ReplyWithAuthor` shapes the existing hooks return, so `SliceFeedPanel`, `PostCard`, `ThreadView` and `ReplyCard` need no changes to their props. `canReadConversationsIn` gets its new body. Members keep the existing block-filtered RPCs; non-members get the public ones. Nothing in this plan may merge before 18-02's grants are applied.

**Tech Stack:** React 19, TanStack Query, `@supabase/supabase-js`, wouter; Playwright (global install, `npm root -g`) for the browser guards.

**Spec:** `.planning/phases/18-the-public-square/18-CONTEXT.md` — D-29, D-30, D-31, D-46, D-48, D-49, and the `locatePost` item under "Flagged for planning".

**Depends on:** 18-02, **applied**, not merely merged.

## Global Constraints

- 🔴 **This plan must not merge before 18-02's grants are live in production.** `main` auto-deploys in ~3 minutes. A frontend that calls `get_public_feed` before the grant exists shows an error to every signed-out visitor; a frontend that flips `canReadConversationsIn` before the RPCs exist renders an empty feed, which reads as *"nobody has said anything here"* — the codebase's own words for a lie told silently.
- **Members keep `get_feed_filtered` / `get_boosted_feed_filtered`.** Those apply block filtering; the public RPCs do not and must not. Routing a member through the public path would silently un-block people they blocked.
- **No new hook may be called inside `SliceFeedPanel`.** All six feed panels mount at once, so a hook there fires 6×. Follow the established pattern: hoist to `AppShell` and pass down, or render the component only for the active tab.
- **`author_user_id === null` means the narrow projection.** Never a sentinel string, never `''`. A null author id means: no avatar, no profile link, no friend affordance — render the handle as plain text.
- **Dark mode and mobile are not optional.** Every visual change is judged on light + dark × desktop + mobile; write the light value and its `dark:` counterpart together, every time.
- **`npm run build` (`tsc -b && vite build`) is the only CI check.** The guards in this plan are manual and must be run by hand before claiming anything.

## Review Focus

Input classes the spec implies that no task's assertions would otherwise reach:

1. **A public place with a `slices` row but zero posts** must say "nobody has posted here yet", not render the Phase 17 "nobody has joined yet" copy — the two are now distinguishable and conflating them is the lie the AppShell comment warns about. Covered in Task 2, Step 1.
2. **A public place with no `slices` row at all.** `get_public_slice` returns zero rows; this is the *common* case (15 slice rows in the entire product) and must be a calm empty state, not an error. Covered in Task 2, Step 1.
3. **A mixed-visibility thread.** One author with an avatar and a profile link, the rest as plain handles, in the same list. The components must tolerate a per-row null author id without a layout jump. Covered in Task 3, Step 4.
4. **A volunteer slice while signed out.** `canReadConversationsIn` must stay false and the feed must not call the public RPC at all. Covered in Task 1, Step 1.
5. **A `/post/:postId` deep link to a public post while signed out.** The new `public` outcome must render the thread rather than stashing to `cs_pending_post` and bouncing through a login that returns to the wrong place. Covered in Task 4.
