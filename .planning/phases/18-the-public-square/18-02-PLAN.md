# Phase 18-02: The public read path in the database

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make City / County / State / Federal / Unified conversations readable without an account, through `SECURITY DEFINER` RPCs that are the only thing `anon` may touch.

**Architecture:** Four `SECURITY DEFINER` functions in `civic_spaces` own the whole public surface. `anon` receives schema `USAGE` and `EXECUTE` on exactly those four, and no table, view, column or sequence grant anywhere. The per-author projection (D-48, D-49) lives in one shared helper that all four call, so the rule has one body. No RLS policy is added for `anon` — which is what keeps Realtime, PostgREST's table routes and every future `select()` closed by construction.

**Tech Stack:** Postgres / Supabase migrations (plpgsql + SQL functions); Node 22 `--experimental-strip-types` and `@supabase/supabase-js` for the guard.

**Spec:** `.planning/phases/18-the-public-square/18-CONTEXT.md` — D-26 through D-31, D-34, D-44, D-46, D-47, D-48, D-49.

**Depends on:** 18-01, which must be **applied** before this plan's migration is applied. 18-01 closes the `public.*` route; this plan opens the `civic_spaces` one, and opening it first would make `GET /rest/v1/posts` live.

## Global Constraints

- 🔴 **`anon` gets schema `USAGE` and four `EXECUTE` grants. Nothing else. Ever.** No `GRANT SELECT` on any table, view or column in `civic_spaces`. If a step seems to need one, the function is wrong, not the grant.
- 🔴 **No RLS policy is added for `anon` or widened to include it.** Every policy in `20260327000002_rls.sql` and `20260917000000_sibling_slice_read_access.sql` stays `TO authenticated`, untouched. A permissive `TO anon` policy on `posts` would make Realtime deliver live rows to anonymous sockets and re-open the PostgREST table route — both are D-44's whole reason for existing.
- **Every function is `SECURITY DEFINER`, `STABLE`, and `SET search_path = ''`**, with every object reference schema-qualified. A `SECURITY DEFINER` function without a pinned `search_path` is a privilege-escalation hole.
- **The public slice types are exactly** `('city','county','state','federal','unified')`. `volunteer` is excluded, and so is anything added to `slices_slice_type_check` later (D-28 — allowlist, never denylist).
- **No function returns:** `edit_history`, `is_deleted`, `account_standing`, `tier`, `current_member_count` (D-34), or `user_id` for an author the viewer cannot see in full (D-31, D-48, D-49).
- **Soft-deleted posts and replies, and posts by suspended authors, are excluded** from every public result.
- Migrations end with `NOTIFY pgrst, 'reload schema';` and need 1–2 minutes before a dependent frontend deploys.
- 🔴 **This plan produces reviewed `.sql` and a guard. It does not apply DDL to production.** Re-run D-24's production aggregate immediately before applying; applying is Chris's call and Chris's hands.

## Review Focus

Input classes the spec implies that no task's assertions would otherwise reach:

1. **A viewer who is a member of the slice AND a friend of one author.** The two unlock paths (D-48, D-49) must not double-count or conflict; the result is the wide projection either way. Covered in Task 2, Step 1.
2. **A pending or rejected friendship.** `civic_spaces.friendships` carries `status`; only `'accepted'` unlocks D-49. A request someone sent and you ignored must not widen anything. Covered in Task 2, Step 1.
3. **A jurisdiction with more than one shard.** D-46 picks the lowest `sibling_index`; production has none today, so this is only ever exercised by a fixture. Covered in Task 3, Step 1.
4. **A post whose author has no `connected_profiles` row.** Today's hooks fall back to `'Unknown'`; the RPC must too, rather than dropping the row and silently shortening a thread. Covered in Task 4, Step 1.
5. **An authenticated member calling the public RPC for their own slice.** They must get the wide projection, not be refused for using the wrong door — otherwise 18-03 has to branch its call sites on membership and D-44's "one read path" evaporates. Covered in Task 3, Step 5.

### Task 3: `get_public_slice` and `get_public_feed`

**Files:**
- Modify: `supabase/migrations/20261030000100_public_read.sql` (sections 2–3)

**Interfaces:**
- Consumes: `public_author_is_visible` from Task 2.
- Produces:

  🔴 `author_user_id` and `author_avatar_url` are **NULL per row** where `public_author_is_visible` is false. 18-03 reads NULL as "narrow projection"; it must never be a sentinel string.

- [ ] **Step 1: Write the assertions as a rehearsal script**

Against seeded fixtures — a city slice with two shards, a volunteer slice, a soft-deleted post, a post by a suspended author, a post whose author has no profile row:

```
- a volunteer slice returns 0 rows from get_public_slice      (D-27)
- a type absent from the allowlist returns 0 rows             (D-28)
- a place with no slices row returns 0 rows                   (not an error)
- a two-shard city returns exactly 1 row, sibling_index = 1   (D-46)
- get_public_feed excludes the soft-deleted post
- get_public_feed excludes the suspended author's post
- get_public_feed returns no edit_history column at all       (D-31)
- get_public_feed returns no current_member_count anywhere    (D-34)
- anon (viewer NULL): author_user_id and author_avatar_url are NULL on every row
- a member of the slice: both are non-NULL on every row

```

- [ ] **Step 2: Run the rehearsal and verify it fails**

Expected: `function civic_spaces.get_public_slice does not exist`.

- [ ] **Step 3: Implement `get_public_slice`**

Filters `civic_spaces.slices` by `p_slice_type = ANY (ARRAY['city','county','state','federal','unified'])` **and** `slice_type = p_slice_type` and `geoid = p_geoid`, orders by `sibling_index`, `LIMIT 1`. 🔴 Write the allowlist as a literal array in the function body, not as a lookup against `slices_slice_type_check` — the constraint says what *may exist*, this says what is *public*, and binding them makes every new type public on creation.

- [ ] **Step 4: Implement `get_public_feed`**

Resolves its shard through `get_public_slice` rather than repeating the rule, then selects non-deleted posts whose author is not suspended, newest first, with the `(created_at, id)` composite cursor `useFeed.ts` already uses. Each row's `author_user_id` / `author_avatar_url` are emitted through a `CASE` on `public_author_is_visible(civic_spaces.current_user_id(), p.user_id, p.slice_id)`. `author_display_name` is `COALESCE(cp.display_name, 'Unknown')` and is always returned.

Expected: all pass. 🔴 The member-calling-the-public-RPC assertion is the one that must not be skipped: if a member gets refused or narrowed here, 18-03 has to branch every call site on membership and D-44's single read path is gone.

### Task 5: The grants — the one-way door

**Files:**
- Create: `supabase/migrations/20261030000200_public_read_grants.sql`

**Interfaces:**
- Consumes: the four functions from Tasks 2–4.
- Produces: the only `anon` privileges in `civic_spaces`.

🔴 **This is the irreversible step. It is a separate migration from the functions on purpose**, so the functions can be reviewed, rehearsed and even applied while the door stays shut, and so the thing that opens it is four lines a human can read in one glance.

- [ ] **Step 1: Write the migration**

```sql
GRANT USAGE ON SCHEMA civic_spaces TO anon;
GRANT EXECUTE ON FUNCTION civic_spaces.get_public_slice(text, text) TO anon;
GRANT EXECUTE ON FUNCTION civic_spaces.get_public_feed(text, text, integer, timestamptz, uuid) TO anon;
GRANT EXECUTE ON FUNCTION civic_spaces.get_public_post(uuid) TO anon;
GRANT EXECUTE ON FUNCTION civic_spaces.get_public_replies(uuid, integer, timestamptz, uuid) TO anon;
NOTIFY pgrst, 'reload schema';
```

Head it with the D-43 warning: `anon` now resolves the `civic_spaces` schema, so **every** table in it is one stray `GRANT SELECT` away from being public, and `check:anon-read` is what stands between. Note that `public_author_is_visible` is deliberately **not** granted — it is an internal helper and a public `EXECUTE` on it would let anyone probe friendships one pair at a time.

- [ ] **Step 2: Rehearse in a transaction and verify anon can call all four**

Expected: four calls succeed as `anon`, returning rows for a public place and zero rows for a volunteer one.

- [ ] **Step 3: Rehearse and verify anon can still read NO table**

In the same transaction, as `anon`: `SELECT` on `civic_spaces.posts`, `replies`, `slices`, `slice_members`, `connected_profiles`, `friendships`, `notifications`.
Expected: `permission denied` on every one. 🔴 Schema `USAGE` changes the error from "schema does not exist" to "permission denied for table" — both refuse, and anyone reading logs should know which to expect.

- [ ] **Step 4: Rehearse and verify `public_author_is_visible` is not callable by anon**

Expected: `permission denied for function`.

- [ ] **Step 5: Commit**

```bash
git add supabase/migrations/20261030000200_public_read_grants.sql
git commit -m "feat(public): grant anon USAGE and four EXECUTEs, and nothing else"
```
