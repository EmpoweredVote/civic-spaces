  <action>
    **1a. Create `src/lib/cursors.ts`:**
    - Export `FeedCursor` type: `{ created_at: string; id: string }` (ISO timestamp + UUID)
    - Export `encodeCursor(cursor: FeedCursor): string` — base64url encode JSON
    - Export `decodeCursor(encoded: string): FeedCursor` — base64url decode + parse
    - The composite cursor prevents duplicates when posts share the same timestamp

    **1b. Create `src/hooks/useFeed.ts`:**
    - Export `useFeed(sliceId: string | null)` hook
    - Uses `useInfiniteQuery` from TanStack Query v5
    - Query key: `['feed', sliceId]`
    - Page size: 20 posts
    - Query function:
      ```
      supabase
        .from('posts')
        .select('*, author:connected_profiles!user_id(display_name, avatar_url)')
        .eq('slice_id', sliceId)
        .eq('is_deleted', false)
        .order('created_at', { ascending: false })
        .order('id', { ascending: false })
        .limit(PAGE_SIZE)
      ```
    - For subsequent pages (when `pageParam` cursor exists), apply composite cursor filter using `.or()`:
      ```
      .or(`created_at.lt.${cursor.created_at},and(created_at.eq.${cursor.created_at},id.lt.${cursor.id})`)
      ```
    - `getNextPageParam`: If the page has PAGE_SIZE items, return the cursor from the last item (created_at + id). If fewer, return undefined (no more pages).
    - `initialPageParam`: undefined (no cursor for first page)
    - `enabled`: `!!sliceId`
    - Return the query result directly (data, fetchNextPage, hasNextPage, isFetchingNextPage, isLoading, error)

    IMPORTANT: The supabase client is already configured with `db: { schema: 'civic_spaces' }` so `.from('posts')` queries the civic_spaces schema. Do NOT use `.schema('civic_spaces')` chaining.

    IMPORTANT: The `.select()` uses a PostgREST foreign key join: `connected_profiles!user_id` joins connected_profiles on the user_id column. The `!user_id` hint is needed because there's no formal FK constraint — PostgREST needs the column hint.

    Actually, PostgREST requires a FK relationship for embedded selects. Since posts.user_id does not have a FK to connected_profiles.user_id, we cannot use embedded select syntax. Instead:
    - Query posts only: `.from('posts').select('*').eq('slice_id', sliceId)...`
    - After fetching posts, extract unique user_ids and fetch profiles in a second query: `.from('connected_profiles').select('user_id, display_name, avatar_url').in('user_id', userIds)`
    - Merge the two results in the queryFn, returning `PostWithAuthor[]` per page
    - This two-query pattern is cleaner than adding FK constraints to the existing schema

    **1c. Create `src/hooks/useRealtimeInvalidation.ts`:**
    - Export `useRealtimeInvalidation(sliceId: string | null)` hook
    - Uses `useEffect` to subscribe to Supabase Realtime channel
    - Channel name: `feed-${sliceId}`
    - Subscribe to `postgres_changes` on `civic_spaces.posts` table with filter `slice_id=eq.${sliceId}`
    - Events: INSERT, UPDATE, DELETE
    - On any event: call `queryClient.invalidateQueries({ queryKey: ['feed', sliceId] })`
    - Get queryClient via `useQueryClient()` from TanStack Query
    - Cleanup: unsubscribe on unmount or sliceId change
    - Skip subscription if sliceId is null
    - IMPORTANT: Use `schema: 'civic_spaces'` in the channel subscription config (Realtime needs the schema specified even though the client defaults to it)
  </action>
