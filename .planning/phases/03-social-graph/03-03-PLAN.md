```typescript
export interface BoostedFeedCursor {
  boosted_at: string  // ISO timestamp — the synthetic sort key
  id: string          // UUID tiebreaker
}
```

**Create src/hooks/useBoostedFeed.ts:**
A new hook that calls the get_boosted_feed RPC function via `supabase.rpc()`. Do NOT modify the existing useFeed hook.

Implementation:

1. Define PAGE_SIZE = 20 (same as useFeed).

2. Create `fetchBoostedFeedPage(sliceId, cursor)`:
   - Call `supabase.rpc('get_boosted_feed', { p_slice_id: sliceId, p_limit: PAGE_SIZE, p_cursor_at: cursor?.boosted_at ?? null, p_cursor_id: cursor?.id ?? null })`
   - The RPC returns rows with all post columns plus `boosted_at`.
   - After fetching posts, collect unique user_ids and batch-fetch profiles from connected_profiles (same two-query pattern as useFeed): `.select('user_id, display_name, avatar_url, tier')`. Include `tier` for EmpoweredBadge rendering.
   - Merge posts with author profiles to produce BoostedPostWithAuthor[].
   - Return the merged array.

3. Create `useBoostedFeed(sliceId)`:
   - Uses `useInfiniteQuery` with queryKey `['boosted-feed', sliceId]`.
   - queryFn calls fetchBoostedFeedPage.
   - `getNextPageParam`: if lastPage.length < PAGE_SIZE, return undefined. Otherwise, take the last item's `boosted_at` and `id` as the BoostedFeedCursor.
   - `initialPageParam`: undefined.
   - `enabled`: !!sliceId.

**CRITICAL cursor detail:** The cursor for page 2+ MUST use `boosted_at` from the last row (NOT `created_at`). The RPC function's WHERE clause compares against boosted_at, so sending created_at would cause pagination gaps. This is the single most important detail — verify the cursor extraction uses `last.boosted_at`.

4. Set up Realtime invalidation for the boosted feed. Reuse the same Realtime pattern from useFeed/useRealtimeInvalidation — subscribe to changes on civic_spaces.posts for the given sliceId, and on any INSERT/UPDATE/DELETE event, invalidate the `['boosted-feed', sliceId]` query. If the existing useRealtimeInvalidation hook is parameterized by queryKey, reuse it directly. If not, either make it accept a queryKey parameter or create a parallel subscription in useBoostedFeed.
