  <name>Task 1: Supabase migration with profile RPC functions + Vite SPA fallback</name>
  <files>supabase/migrations/20260404000000_phase8_profile_rpcs.sql, vite.config.ts</files>
  <action>
Create migration `supabase/migrations/20260404000000_phase8_profile_rpcs.sql` with two SECURITY DEFINER functions:

1. `civic_spaces.get_profile_stats(p_user_id text)` - Returns JSON with post_count, reply_count, friend_count.
   - post_count: COUNT from civic_spaces.posts WHERE user_id = p_user_id AND is_deleted = false
   - reply_count: COUNT from civic_spaces.replies WHERE user_id = p_user_id AND is_deleted = false
   - friend_count: COUNT from civic_spaces.friendships WHERE (user_low = p_user_id OR user_high = p_user_id) AND status = 'FRIEND'
   - LANGUAGE sql, STABLE, SECURITY DEFINER, SET search_path = ''
   - GRANT EXECUTE to authenticated

2. `civic_spaces.get_mutual_friends(p_subject_id text)` - Returns TABLE(user_id text, display_name text, tier text).
   - CTE viewer_friends: extract friend_ids where current user is user_low or user_high, status = 'FRIEND', using civic_spaces.current_user_id()
   - CTE subject_friends: extract friend_ids where p_subject_id is user_low or user_high, status = 'FRIEND'
   - JOIN viewer_friends and subject_friends to get intersection
   - JOIN civic_spaces.connected_profiles to get display_name and tier
   - LANGUAGE sql, STABLE, SECURITY DEFINER, SET search_path = ''
   - GRANT EXECUTE to authenticated

All table references MUST be fully qualified with `civic_spaces.` prefix (required for SECURITY DEFINER with search_path = '').

Also update `vite.config.ts`: add `server: { historyApiFallback: true }` to the defineConfig object so that `/profile/:userId` URLs work in dev mode without 404.

Note: Vite doesn't have `historyApiFallback` directly. The correct approach is `appType: 'spa'` (which is default) and no additional config needed for the dev server — Vite automatically serves index.html for unmatched routes in dev. However, verify this works. If direct URL access to `/profile/xxx` in dev returns 404, add a custom middleware or use the `vite-plugin-rewrite-all` approach. Most likely no vite.config change is needed since Vite SPA mode already handles this.
