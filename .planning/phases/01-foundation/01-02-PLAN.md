  <action>
    Create the full schema DDL in `supabase/migrations/20260327000001_schema.sql`. Use the GEOID format confirmed in Plan 01-01's checkpoint (read from 01-01-SUMMARY.md).

    Tables to create (all in `civic_spaces` schema):

    1. **slices** — One row per slice instance
       - `id` uuid PRIMARY KEY DEFAULT gen_random_uuid()
       - `slice_type` text NOT NULL CHECK (slice_type IN ('federal', 'state', 'local', 'neighborhood'))
       - `geoid` text NOT NULL — the jurisdiction GEOID this slice covers
       - `sibling_index` integer NOT NULL DEFAULT 1 — 1 for first slice, 2 for overflow, etc.
       - `current_member_count` integer NOT NULL DEFAULT 0
       - `created_at` timestamptz NOT NULL DEFAULT now()
       - UNIQUE constraint on (geoid, slice_type, sibling_index) — prevents duplicate siblings
       - CHECK constraint: current_member_count <= 6000 (safety net behind the trigger)
       - CHECK constraint: current_member_count >= 0

    2. **slice_members** — Maps users to slices
       - `id` uuid PRIMARY KEY DEFAULT gen_random_uuid()
       - `user_id` text NOT NULL — accounts UUID (text, not uuid, because it comes from auth.jwt() ->> 'sub' which returns text)
       - `slice_id` uuid NOT NULL REFERENCES civic_spaces.slices(id) ON DELETE CASCADE
       - `joined_at` timestamptz NOT NULL DEFAULT now()
       - UNIQUE constraint on (user_id, slice_id) — idempotent upserts

    3. **connected_profiles** — Minimal local profile for Connected-tier users (NOT a copy of the accounts profile — only display_name for fast reads)
       - `user_id` text PRIMARY KEY — accounts UUID
       - `display_name` text NOT NULL
       - `account_standing` text NOT NULL DEFAULT 'active' CHECK (account_standing IN ('active', 'suspended'))
       - `created_at` timestamptz NOT NULL DEFAULT now()
       - `updated_at` timestamptz NOT NULL DEFAULT now()
       Note: display_name is synced from accounts API on login (by the slice assignment service). This is the ONLY place display_name is stored locally — it exists for JOIN performance so the feed doesn't require N+1 API calls.

    4. **posts** — Forum posts within a slice
       - `id` uuid PRIMARY KEY DEFAULT gen_random_uuid()
       - `slice_id` uuid NOT NULL REFERENCES civic_spaces.slices(id) ON DELETE CASCADE
       - `user_id` text NOT NULL — accounts UUID, author
       - `title` text — optional, can be null for short posts
       - `body` text NOT NULL
       - `created_at` timestamptz NOT NULL DEFAULT now()
       - `updated_at` timestamptz NOT NULL DEFAULT now()
       - `is_deleted` boolean NOT NULL DEFAULT false — soft delete

    5. **replies** — Replies to posts (supports one level of nesting: reply to post, reply to reply)
       - `id` uuid PRIMARY KEY DEFAULT gen_random_uuid()
       - `post_id` uuid NOT NULL REFERENCES civic_spaces.posts(id) ON DELETE CASCADE
       - `parent_reply_id` uuid REFERENCES civic_spaces.replies(id) ON DELETE CASCADE — null = direct reply to post
       - `user_id` text NOT NULL — accounts UUID, author
       - `body` text NOT NULL
       - `created_at` timestamptz NOT NULL DEFAULT now()
       - `updated_at` timestamptz NOT NULL DEFAULT now()
       - `is_deleted` boolean NOT NULL DEFAULT false

    **Indexes:**
    - `slice_members`: index on (user_id) for fast membership lookups in RLS
    - `slice_members`: index on (slice_id) for listing members
    - `slices`: index on (geoid, slice_type) for slice lookup by jurisdiction
    - `posts`: index on (slice_id, created_at DESC) for feed pagination
    - `replies`: index on (post_id, created_at) for thread rendering

    **Important:**
    - Use `text` for user_id columns, NOT `uuid`. The value comes from `auth.jwt() ->> 'sub'` which returns text. Casting to uuid in every RLS policy is error-prone.
    - Do NOT create a separate users table. connected_profiles serves that purpose minimally.
    - Grant SELECT, INSERT, UPDATE, DELETE on all tables to `authenticated` role.
    - Grant USAGE, SELECT on all sequences to `authenticated` role.

    **RLS Policies** (`supabase/migrations/20260327000002_rls.sql`):

    Enable RLS on ALL tables first:
    ```sql
    ALTER TABLE civic_spaces.slices ENABLE ROW LEVEL SECURITY;
    ALTER TABLE civic_spaces.slice_members ENABLE ROW LEVEL SECURITY;
    ALTER TABLE civic_spaces.connected_profiles ENABLE ROW LEVEL SECURITY;
    ALTER TABLE civic_spaces.posts ENABLE ROW LEVEL SECURITY;
    ALTER TABLE civic_spaces.replies ENABLE ROW LEVEL SECURITY;
    ```

    Then create policies:

    **slices:**
    - SELECT for authenticated: USING (true) — all authenticated users can see slice metadata (names, types). No sensitive data in this table.

    **slice_members:**
    - SELECT for authenticated: USING (user_id = civic_spaces.current_user_id()) — users can see their own memberships
    - INSERT: handled by service role only (slice assignment service), no authenticated INSERT policy needed
    - DELETE: handled by service role only

    **connected_profiles:**
    - SELECT for authenticated: USING (true) — display_name is public within the app (needed for post/reply author display)
    - UPDATE for authenticated: USING (user_id = civic_spaces.current_user_id()) WITH CHECK (user_id = civic_spaces.current_user_id()) — users can update their own profile only

    **posts:**
    - SELECT for authenticated: user must be a member of the post's slice
      ```sql
      USING (
        slice_id IN (
          SELECT sm.slice_id FROM civic_spaces.slice_members sm
          WHERE sm.user_id = civic_spaces.current_user_id()
        )
        AND is_deleted = false
      )
      ```
    - INSERT for authenticated: user_id must match current user AND slice_id must be one of their slices
      ```sql
      WITH CHECK (
        user_id = civic_spaces.current_user_id()
        AND slice_id IN (
          SELECT sm.slice_id FROM civic_spaces.slice_members sm
          WHERE sm.user_id = civic_spaces.current_user_id()
        )
      )
      ```
    - UPDATE for authenticated: user owns the post (for editing)
      ```sql
      USING (user_id = civic_spaces.current_user_id() AND is_deleted = false)
      WITH CHECK (user_id = civic_spaces.current_user_id())
      ```
    - DELETE: use soft delete via UPDATE (set is_deleted = true), no hard DELETE policy for authenticated

    **replies:**
    - SELECT for authenticated: user must be a member of the parent post's slice
      ```sql
      USING (
        post_id IN (
          SELECT p.id FROM civic_spaces.posts p
          WHERE p.slice_id IN (
            SELECT sm.slice_id FROM civic_spaces.slice_members sm
            WHERE sm.user_id = civic_spaces.current_user_id()
          )
        )
        AND is_deleted = false
      )
      ```
    - INSERT for authenticated: user_id must match AND parent post must be in user's slice
      ```sql
      WITH CHECK (
        user_id = civic_spaces.current_user_id()
        AND post_id IN (
          SELECT p.id FROM civic_spaces.posts p
          WHERE p.slice_id IN (
            SELECT sm.slice_id FROM civic_spaces.slice_members sm
            WHERE sm.user_id = civic_spaces.current_user_id()
          )
        )
      )
      ```
    - UPDATE for authenticated: user owns the reply

    **Triggers** (`supabase/migrations/20260327000003_triggers.sql`):

    1. **enforce_slice_cap** — BEFORE INSERT on slice_members:
       - SELECT current_member_count FROM civic_spaces.slices WHERE id = NEW.slice_id FOR UPDATE
       - IF count >= 6000: RAISE EXCEPTION 'slice_full: ...' USING ERRCODE = 'P0001'
       - Otherwise: UPDATE slices SET current_member_count = current_member_count + 1
       - RETURN NEW

    2. **decrement_slice_count** — AFTER DELETE on slice_members:
       - UPDATE civic_spaces.slices SET current_member_count = current_member_count - 1 WHERE id = OLD.slice_id
       - RETURN OLD

    3. **update_updated_at** — BEFORE UPDATE on connected_profiles, posts, replies:
       - SET NEW.updated_at = now()
       - RETURN NEW
       Create one function, attach as trigger to all three tables.

    **Seed Data** (`supabase/seed.sql`):

    Create test data for verifying the schema and cap enforcement:
    - 2 federal slices for different GEOIDs (e.g., 'IN09' and 'CA12')
    - First slice has current_member_count = 5999 (near cap) — insert 5999 dummy members
    - A few test posts and replies in the first slice
    - 3 connected_profiles for test users

    The seed should be runnable via `supabase db reset` and should demonstrate:
    - Member 6000 can be inserted (cap not yet reached)
    - Member 6001 raises 'slice_full' exception
    - Deleting a member decrements the count

    Use realistic but fake UUIDs for user_ids (e.g., 'test-user-001', 'test-user-002', etc. — remember user_id is text, not uuid).

    IMPORTANT: For the 5999-member seed, do NOT insert 5999 individual rows. Instead:
    - Insert the slice with current_member_count = 5999 directly (bypassing the trigger by using a service-role-style approach)
    - OR: Use generate_series to bulk-insert, then verify the trigger count matches
    - The simplest approach: INSERT the slice row, then UPDATE current_member_count = 5999 directly (triggers only fire on slice_members, not on slices). Then insert 1 real member to hit 6000, and try a second to test the cap.
