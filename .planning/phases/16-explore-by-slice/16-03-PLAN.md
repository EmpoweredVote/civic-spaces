# Phase 16-03 — `ExploreView` renders the composition

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `ExploreView` from a fixed five-section page into a renderer of
`composition.modules`, so Federal differs from City **structurally** and not only in its
wording — and so every coming Connect feature has a slot to arrive into.

**Architecture:** `ExploreView` becomes: resolve the composition through the seam, build the
context, walk `composition.modules`, render each module or its declared empty room. Its five
inline sections are deleted in favour of 16-02's module files. `TopicDetail` stays, taking a
resolved topic rather than an id. `cs_explore_ui.openTopic` becomes composition-scoped —
without that, a city topic renders on the State tab the moment 16-04 lands.

**Tech Stack:** React 19 · TypeScript 5.7 · Vite 6 · TanStack Query · no test framework (see `16-SHARED.md`).

**Spec:** `16-DESIGN.md` ("The shape this implies"), `16-RESEARCH.md` **Finding 3** items 1,
2, 4, 6 and **Pitfall 1**.

**Depends on:** 16-02. **Execute serially after it** — see the plan-set table in 16-01.

**Carries:** locked decision 1; research Finding 3 items 1, 2, 4; Pitfall 1.

### Task 1: Scope `openTopic` to a composition

🔴 Pitfall 1, and it is a correctness bug rather than tidiness. `cs_explore_ui` is one global
record (`exploreStorage.ts:33-37`) and `ExploreView.tsx:165` renders
`ui.openTopic && TOPICS[ui.openTopic]`. Today that is harmless because every tab shows the
same topics. The moment Explore follows the tab (16-04), a member who opens a City topic and
switches to State gets a **city topic rendered on the State tab**, with a Join button
targeting a different jurisdiction's composition.

Landing it here, one plan early, means 16-04 cannot introduce the bug even briefly.

**Files:**
- Modify: `src/components/explore/exploreStorage.ts:33-37, 48-55, 81-87`

- [ ] **Step 1: The shape**

```ts
export interface ExploreUiState {
  /** Scoped: which composition it was opened in, and which topic. */
  openTopic: { key: string; topicId: string } | null
  imagine: ImagineOption | null
  adventure: AdventureDuration | null
}
```

- [ ] **Step 2: Guard the read**

`read()` is an unchecked `JSON.parse(...) as T` (`:48-55`), so a value stored before this
change has `openTopic` as the bare string `'safer-walking'` — which will not throw, it will
be silently mis-typed and then used as an object.

In `readUiState`, coerce `openTopic` to `null` unless it is an object with a string `key`
**and** a string `topicId`. Keep the `cs_explore_ui` key name: `imagine` and `adventure` are
still valid and worth preserving across the change. (Drafts and the resume marker *do* get
new key names — that is 16-04, where the shape change is larger and a stale read is worse.)

- [ ] **Step 3: Typecheck and commit**

Run: `npm run build`

Expected: errors only in `ExploreView.tsx`, at the three places that read or write
`ui.openTopic` (`:130-136`, `:165-189`, `:174-186`). 🔴 **Do not commit red.** Either fix
those three call sites in this same commit — they are mechanical, since this task does not
change what `openTopic` means to them — or fold this task into Task 2. Whichever you choose,
the commit that lands is green.

```bash
git add src/components/explore/exploreStorage.ts src/components/explore/ExploreView.tsx
git commit -m "feat(explore): scope the open topic to its composition"
```

### Task 2: `ExploreView` renders the composition

The refactor's centre. After this task `ExploreView` contains no section markup at all: it
resolves, builds the context, walks the list, and owns `TopicDetail`.

**Files:**
- Modify: `src/components/explore/ExploreView.tsx` (substantial)

**Interfaces:**
- Consumes: `useExploreComposition` (16-01), `MODULE_REGISTRY`, `ExploreCtx` (16-02).
- Produces: `<ExploreView sliceType geoid destination isAuthenticated meetings elections
  featuredPhoto onStartConversation onScrollTop whatsNewInSidebar onGoToView />` — today's
  props plus `sliceType` and `geoid`.

- [ ] **Step 1: The body**

```tsx
const { composition, isLoading } = useExploreComposition({ sliceType, geoid })
if (isLoading) return <ExploreSkeleton />          // react-loading-skeleton, matching FeedSkeleton
if (!composition) return null                      // volunteer: no Explore, unchanged

// Module-owned topics merge in before the composition's own, so a module can
// always open what it offers (Research Finding 3 item 3).
const topicsById = new Map<string, ExploreTopic>()
for (const id of composition.modules) {
  for (const t of MODULE_REGISTRY[id].topics?.(composition) ?? []) topicsById.set(t.id, t)
}
for (const t of composition.topics) topicsById.set(t.id, t)

const ctx: ExploreCtx = { composition, topicsById, /* …the rest… */ }

// Topic detail replaces the whole view — but ONLY for this composition's topics.
const open = ui.openTopic
if (open && open.key === composition.key) {
  const topic = topicsById.get(open.topicId)
  if (topic) return <TopicDetail topic={topic} ctx={ctx} />
}

return (
  <div className="@container flex flex-col gap-6 @lg:gap-8 pb-2">
    {composition.modules.map((id) => {
      const mod = MODULE_REGISTRY[id]
      if (mod.available(ctx)) return <mod.Component key={id} ctx={ctx} />
      if (mod.emptyState === 'hide') return null
      return <ReservedRoom key={id} id={id} {...mod.emptyState} />
    })}
  </div>
)
```

Two notes on the double guard around `open`: the key check handles a tab change; the
`topicsById.get` check handles a topic that has since left the composition (a Compass
re-rank, or an agenda item that rolled off). When either fails, fall through to the list —
silently, not with an error. The member pressed nothing; there is nothing to apologise for.

Give each rendered module a `data-explore-module={id}` wrapper attribute, matching
`ReservedRoom`'s `data-explore-room`. 16-10's harness reads the composition off the page, and
that is what turns "visibly different compositions" from an opinion into an observation.
