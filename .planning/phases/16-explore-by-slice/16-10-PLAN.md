# Phase 16-10 — The four-way visual pass and the phase gate

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the five lines of the verification bar, in the running app, in all four
presentations — and then ship.

**Architecture:** This plan builds almost nothing. It adds one harness script and then uses
it, the two checks from 16-05 and 16-08, and a pair of eyes. A finding becomes a commit
against the file at fault, in whichever plan's territory it lands. It either passes or it
sends you back, and sending you back is a successful outcome for this plan.

🔴 **A clean run only proves the pixels decoded.** `scripts/shoot-banners.mjs`'s own lesson,
recorded in `CLAUDE.md`: a script that exits 0 having written 28 PNGs has verified that 28
PNGs are writable. **Look at the images.** Then drive the page and hit-test the controls,
because PR #92 shipped a photo credit whose licence link sat under the content layer's
padding — a control that rendered perfectly, was invisible to every screenshot and to
`tsc -b`, and could not be clicked at `md` and up, so phones looked fine.

**Tech Stack:** Playwright (**a global install, not in `node_modules`**) · Node 24 · no test
framework (see `16-SHARED.md`).

**Spec:** `16-CONTEXT.md` **"Verification bar"** — the five lines are this plan's acceptance
criteria, reproduced below. `CLAUDE.md` "Design rules" for the four-way standard, the
contrast rule and the harness pattern.

**Depends on:** every other plan in the phase.

**Carries:** the whole verification bar; `CLAUDE.md`'s four-way standard and contrast rule.

## The bar

From `16-CONTEXT.md`. Not "it compiles". Phase 16 is done when:

1. Federal, State, City/County and Unified resolve to **visibly different** compositions.
2. **Bloomington** carries real agenda-derived content end to end, proving the bespoke layer.
3. A sibling shard shows Explore with **no** write affordance anywhere in it.
4. A draft started on one tab **cannot** post to another jurisdiction.
5. Light + dark, desktop + mobile all check out.

Lines 1–4 each had a check built in the plan that created them. This plan re-runs all of
them together — a phase passes as a whole or not at all — and line 5 is its own work.

### Task 1: The harness

**Files:**
- Create: `scripts/shoot-explore.mjs`
- Modify: `package.json`, `.gitignore`
- Reference (do not edit): `scripts/shoot-app.mjs` — `loadChromium()` (`:75-93`), the
  one-context/one-load/many-shots structure (`:108-118`) and the theme toggle (`:148-152`);
  `scripts/shoot-banners.mjs` — the harness-page pattern

- [ ] **Step 1: Write it**

🔴 **Most of this needs no token. One part of it does, and the plan has to say which.**

`shoot-app.mjs` needs a real `cs_token` because it drives the signed-in shell. Explore mostly
does not: `?dev=1` opens on the reserved `dev-guest` id with fixture slices and **real public
data** through the `/api` proxy, 16-06 added `&place=bloomington`, and 16-05 added a City
sibling so the view-only state is reachable too.

**But the genuinely signed-out shots are not reachable on a fresh clone.** With no
`VITE_SUPABASE_URL`, `useAuth` enters dev-guest mode unconditionally — `import.meta.env.DEV
&& (?dev=1 || !VITE_SUPABASE_URL)` (`useAuth.ts:219-225`) — so dropping `?dev=1` does not
sign you out, it keeps you signed in. Reaching the signed-out branch (`AppShell.tsx:866-886`)
needs `VITE_SUPABASE_URL` set in `.env.local` **and** no `cs_token`. That is a real-backend
configuration, not a credential, but it is a setup step and the script must say so rather
than silently shooting the dev-guest page and labelling it "signed out".

So split the run, and make the second group's requirement explicit in the script's output:

| Group | Needs | Place | Tabs | × | Output |
|---|---|---|---|---|---|
| **A — default** | nothing | `?dev=1&place=bloomington` (seeded) | City, County, State, Federal, Unified | light/dark × desktop/mobile | 20 |
| **A** | nothing | `?dev=1` (Asheville, unseeded) | City | same | 4 |
| **A** | nothing | `?dev=1`, **view-only** (switch to City Slice 2, then Explore) | City | same | 4 |
| **B — opt-in** | `VITE_SUPABASE_URL` in `.env.local`, no `cs_token` | signed out | — | same | 4 |

Group A is **28 PNGs and runs on a fresh clone.** Group B adds 4 and is skipped with a
printed line — *"signed-out shots skipped: set VITE_SUPABASE_URL in .env.local to reach the
signed-out branch; with no backend configured the app always enters dev-guest mode"* — when
the environment is not configured. 🔴 A skip must never be reported as a pass, and the four
missing presentations must be named in the run's summary so nobody reads 28/28 as complete.

The view-only group is here rather than in 16-05 on purpose: that plan proves the gate
functionally, this one is the only place its **appearance** is judged, and the amber notice
plus a form-less topic page is a layout nobody has looked at in dark mode.

One browser, one context, **one page load per group**, then manipulate the live page: switch
tabs by clicking (which is what `AppShell` actually does — every panel is already mounted, so
a tab switch is a CSS reveal, not a fetch), toggle the theme in-page, and resize. Reloading
per combination is both slower and less faithful.

Write to `explore-shots/` (gitignored, like `banner-shots/`). Viewports from
`shoot-app.mjs`: `1440×1000` and `390×844`, `deviceScaleFactor: 2`.

Per shot, also print what was on screen — the point of `shoot-app.mjs`'s `seen` block is that
a screenshot cannot tell "absent" from "scrolled out of view":

- the module ids present, in order (from `[data-explore-module]` / `[data-explore-room]`)
- the count of reserved rooms
- whether the agenda section rendered, and its item count
- the first heading text
- `window.scrollY` on arrival

- [ ] **Step 2: Add the data attribute if it is not there**

16-09 added `data-explore-room` to `ReservedRoom`. Add the matching
`data-explore-module={id}` in `ExploreView`'s registry walk. One attribute makes the
composition machine-readable from the page, which is what turns line 1 of the bar from an
opinion into an observation.

- [ ] **Step 3: Run it**

```bash
npm run dev
npm run shoot:explore
```

Expected: **28 files from group A**, zero page errors, and a printed module list per shot.
Plus 4 more if group B is configured, or a printed skip line naming the four that are
missing. The run must not exit 0 claiming completeness when group B was skipped — print the
skip prominently and let the human decide whether to configure it.

- [ ] **Step 4: Commit**

```bash

git commit -m "feat(dev): four-way Explore harness, no credential needed"
```

### Task 3: Hit-test, and check the contrast properly

Two failure classes a PNG cannot show.

- [ ] **Step 1: Hit-test every primary control — the PR #92 pass**

Drive the live page and, for each module's primary control on each tab, at **both** viewports:

```js
const r = el.getBoundingClientRect()
const hit = document.elementFromPoint(r.left + r.width / 2, r.top + r.height / 2)
// hit must be el, or a descendant of el
```

Controls to cover: the featured card's "Explore this topic"; a question card; Imagine's
radios and its Share button; the Nearby time picker and its dialog's "Save on this device";
an agenda topic card; a race card's links; a debate's watch link; the seed invitation's one
control; every `sourceUrl` and licence link.

🔴 PR #92's bug was **only at `md` and up**, so phones looked fine and the desktop shots did
too. Run both viewports and treat a `md`-only failure as the expected shape of this bug, not
an oddity.

When something fails: fix the layering, then **toggle the suspect class off mid-run and
re-test**. A fix that is load-bearing will put the bug straight back. If removing it changes
nothing, you fixed something else and the real bug is still there.

- [ ] **Step 2: Contrast, through a canvas**

🔴 Tailwind v4 emits `oklch()`. A check that reads `getComputedStyle(el).color` and parses it
as `rgb()` will give you confident, wrong numbers — the repo has been burned by exactly this.
Paint the resolved colour into a 1×1 canvas and read the pixel back; do the same for the
effective background; compute the ratio from those.

Measure, in both themes:

| Element | Threshold |
|---|---|
| Every body and small-print run in the new modules | **4.5:1** |
| Any icon carrying meaning | **3:1** |
| The reserved rooms' body text (deliberately quieter — the easiest to under-contrast) | 4.5:1 |
| The seed invitation's "arrives next" line (`text-xs`) | 4.5:1 |
| The view-only notice's amber text, light and dark | 4.5:1 |
| Provenance tags and the generated-summary label | 4.5:1 — 🔴 an honesty label nobody can read is not an honesty label |

- [ ] **Step 3: Reduced motion**

With `prefers-reduced-motion: reduce`, load every tab. Nothing animates. The repo's
`motion-safe:` prefixes and `motion/react` handle this — confirm, do not assume, and check
the seed invitation specifically since 16-08 allowed it an entrance.

- [ ] **Step 4: Commit the fixes**

One commit per file at fault, each naming what it fixes.
