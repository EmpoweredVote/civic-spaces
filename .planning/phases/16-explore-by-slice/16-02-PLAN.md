# Phase 16-02 — The registry contract and the content modules

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the contract a module declares, and move Explore's five hard-coded sections
into modules that satisfy it — without changing what the app renders yet.

**Architecture:** One context object (`ExploreCtx`) carries the things every module needs, so
nothing is re-threaded prop by prop. One registry maps each `ModuleId` to
`{ available, Component, emptyState, topics? }`. The five sections currently inlined in
`ExploreView.tsx:198-301` become components under `components/explore/modules/`, largely
intact — this is a re-seating, not a rewrite of their markup — with three real behaviour
fixes folded in: the intro copy becomes level-aware, the "Sample" badges become
provenance-driven, and the question-card icon is chosen by content rather than by array
index. `AdventureActivity` splits into its two unrelated halves.

🔴 **Nothing changes on screen in this plan.** `ExploreView` still renders its own inline
sections; the new modules exist, are registered, and are not yet called. That is deliberate:
16-03 does the switch-over as one reviewable change, and it keeps every commit here green.
The brief duplication between the inline sections and the module files lives for exactly one
plan.

**Tech Stack:** React 19 · TypeScript 5.7 (`strict`, `noUncheckedIndexedAccess`,
`noUnusedLocals`, `noUnusedParameters`) · Vite 6 · Tailwind v4 (no config file) · no test
framework (see `16-SHARED.md`).

**Spec:** `16-DESIGN.md` ("The shape this implies", "Left to the builder"), `16-CONTEXT.md`
(locked decisions 1, 8, 9), `16-RESEARCH.md` **Finding 3** — read Finding 3 in full before
Task 1; it is the inventory of exactly what is coupled and where.

**Depends on:** 16-01. **Execute serially after it** — see the plan-set table in 16-01.

**Carries:** locked decisions 1, 8, 9; research Finding 3 items 1, 2, 3, 5; anti-pattern
"Hiding an empty module silently".

### Task 1: The context, the registry contract, and the honesty labels

Three small files that together are the whole contract. Research Finding 3 derived the
context's membership from what the five existing sections actually read; this is that list,
plus the fields later plans fill in.

**Files:**
- Create: `src/components/explore/ExploreContext.ts`, `registry.tsx`, `provenance.tsx`
- Reference (do not edit): `exploreUi.tsx` (the vocabulary); `ExploreView.tsx:226-228, 277,
  368` (the three hard-coded honesty labels being replaced)

**Interfaces:**
- Consumes: `ExploreComposition`, `ExploreTopic`, `ModuleId`, `TopicProvenance` (16-01).
- Produces: `ExploreCtx`, `ExploreModule`, `MODULE_REGISTRY`, `ReservedRoom`,

- [ ] **Step 1: `ExploreContext.ts`**

```ts
/**
 * What a module gets. One object, passed as a prop — not a React context: there
 * is exactly one consumer tree, and a context would hide which modules depend on
 * what, which is the thing this refactor exists to make visible.
 */
export interface ExploreCtx {
  composition: ExploreComposition
  /**
   * Every topic a module may open, by id. Wider than composition.topics: the
   * Imagine and Nearby modules contribute their own self-contained topics (see
   * ExploreModule.topics), because a module that owns its content must not break
   * when a composition omits an id it happened to reference.
   */
  topicsById: ReadonlyMap<TopicId, ExploreTopic>

  /** Where a post lands. null when signed out or with no slice for this tab. */
  destination: ExploreDestination | null
  isAuthenticated: boolean
  /**
   * True on a sibling shard of the member's own jurisdiction: readable, and every
   * write path closed by RLS. Threaded here and always false until 16-05 wires
   * it, so the gate lands in ONE place and every module inherits it.
   */
  isViewOnly: boolean

  // Data, all hoisted above this component and resolved once for the active tab.
  featuredPhoto: FeaturedPhoto | null
  meetings: UpcomingMeeting[] | undefined
  elections: UpcomingElection[] | undefined

  // UI state and actions.
  ui: ExploreUiState
  setUi: (patch: Partial<ExploreUiState>) => void
  draftFor: (topicId: TopicId) => ExploreDraft
  saveDraft: (topicId: TopicId, patch: Partial<Pick<ExploreDraft, 'title' | 'body'>>) => ExploreDraft
  discardDraft: (topicId: TopicId) => void
  openTopic: (topicId: TopicId | null) => void
  startConversation: (topicId: TopicId) => void
  onGoToView?: (view: 'explore' | 'conversations') => void
  whatsNewInSidebar: boolean
}
```

Add `agenda` in 16-06, `races` / `debates` in 16-07 and `placeName` in 16-08 — do not stub
them now, or `noUnusedLocals` will fight you for four plans.

- [ ] **Step 2: `registry.tsx` — the contract and the empty room**

```tsx
export interface ExploreModule {
  /** May this module render at all, here, now? Pure and cheap: called every render. */
  available: (ctx: ExploreCtx) => boolean
  Component: (props: { ctx: ExploreCtx }) => ReactElement | null
  /**
   * What to show when available() is false.
   *
   * 'hide' means the module genuinely does not belong here — Imagine on Federal.
   * A reserved room means it DOES belong and has no source or is not built yet,
   * and it says so. Hiding an empty module silently is the anti-pattern: a
   * reserved room is how the design gives the coming Connect features somewhere
   * obvious to arrive without re-opening the design.
   *
   * 🔴 A reserved room NEVER renders a placeholder fact and NEVER renders a
   * control. It is a sentence about what this space becomes.
   */
  emptyState: 'hide' | { title: string; body: string }
  /**
   * Topics this module owns and can open, beyond the composition's own list.
   * Imagine and Nearby use it: their option lists name topic ids, and a
   * composition is free not to contain them.
   */
  topics?: (composition: ExploreComposition) => ExploreTopic[]
}

export const MODULE_REGISTRY: Record<ModuleId, ExploreModule> = { /* Tasks 2 and 3 */ }
```

`Record<ModuleId, ExploreModule>` with no index signature means **every** `ModuleId` must
have an entry or the build fails. That exhaustiveness is the point: a composition can never
name a module the registry has not thought about.

To keep the build green from this commit on, point every id not yet written at a placeholder
`ReservedRoom` entry with `available: () => false`. 16-03 Task 4 reviews the whole table and
16-09 writes the final copy. **A temporary `as Record<ModuleId, ExploreModule>` cast is not
acceptable** — it would silently survive into the merge and defeat the exhaustiveness.

`ReservedRoom` is a small presentational component in the same file — a `CARD` with the
title, the body, and nothing clickable. Keep it visually quieter than a real module (no
`PrimaryButton`, muted border) so a page with several does not read as a page full of
features. Give it `data-explore-room={id}`: 16-09's check and 16-10's harness both read the
page's structure, and a stable hook is cheaper than a brittle text selector.

- [ ] **Step 3: `provenance.tsx` — replace the three hard-coded labels**

Today `ExploreView` hard-codes `Sample topic` (`:226-228`), a `· Sample` suffix (`:277`) and
`Conversation starter · not an official proposal` (`:368`). All three are now wrong in both
directions: false-by-omission on an agenda-derived topic, and misleadingly apologetic on a
staff-written one. Drive them from `topic.provenance`:

| provenance | Tag | Source note |
|---|---|---|
| `staff` | "Conversation starter" | "A prompt for discussion, not an official proposal." |
| `chapter` | `topic.sourceLabel` ("From the League of Women Voters") | the chapter, linked via `sourceUrl` when `isHttpUrl` passes |
| `derived-from-agenda` | `topic.sourceLabel` ("Ordinance 2026-22 · Second reading") | "From the {sourceDate} agenda" + the link, **plus** the generated-summary line |
| `derived-from-vote` | `topic.sourceLabel` | the roll call's own link |
| `member` | "Suggested by a member here" | "A neighbour asked for this topic. It is not an official proposal." |

🔴 When `topic.summaryIsGenerated` is true, `SourceNote` must say so in plain words — the
title and reference are the source's own, the summary is a machine-written interpretation.
Presenting generated text as the record is the quietest form of the invented-civic-record
anti-goal, and it is the one a reader cannot detect.

Every `href` built from `topic.sourceUrl` passes `isHttpUrl` (16-01) first and carries
`target="_blank" rel="noopener noreferrer"`.

- [ ] **Step 2: `FeaturedModule`**

Copy `:211-243`. Three changes:

- The topic is `ctx.topicsById.get(ctx.composition.featuredTopicId ?? '')`, guarded — under

- [ ] **Step 4: `ImagineModule`**

This is Research Finding 3 item 3: the module owns its topics, so a composition is free not
to list them.
