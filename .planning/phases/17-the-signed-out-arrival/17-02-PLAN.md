# Phase 17-02 — The gate fails closed, and the notices learn why

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `AppShell` stops computing the write gate inline and starts asking
`whyNoWrite()`. A viewer holding no slice of the tab's type is gated instead of offered a
composer RLS can only refuse, and every read-only notice in the app says *which* of the four
reasons it is and what to do about it.

**Architecture:** One expression is deleted and one function call replaces it. The reason it
returns is threaded to the three places that already render an amber notice —
`SliceFeedPanel`'s feed banner, `ThreadView`'s thread banner, and Explore's
`ViewOnlyNotice` — which become one shared component, because three near-identical notices
is three chances for one of them to be wrong in dark mode, and `ViewOnlyNotice`'s own header
already says so. A new dev fixture place with **no city slice** makes the previously
unreachable branch reachable, and `check:explore-gate` grows its third and fourth viewer
cases.

**Tech Stack:** React 19 · TypeScript 5.7 · Vite 6 · Tailwind v4 · Playwright (**a global
install — not in `node_modules`**) · no test framework (see `17-SHARED.md`).

**Spec:** `17-RESEARCH.md` **Q3.4** — read its four-row table in full before Task 1; it is
this plan's checklist — plus **Pitfalls 1 and 2**; `17-CONTEXT.md` D-01, D-04, D-11, D-20;
`ROADMAP.md` § Phase 17's third scope bullet; `16-CONTEXT.md` locked decision 4, whose gate
this generalises rather than replaces.

**Depends on:** 17-01. **Execute serially after it** — see the plan-set table in
`17-SHARED.md`.

## 🔴 What changes on screen, and the one thing it takes away

Four viewers change state. Three are fixes. One is a deliberate removal, and it must not be
mistaken for a regression.

| Viewer | Today | After this plan |
|---|---|---|
| Member on their own shard | writable | writable — **unchanged, and this is the control case** |
| Member on a sibling shard | gated | gated — unchanged, reason `sibling-shard` |
| Member on a tab they hold **no** slice for | 🔴 **offered a composer** | gated, reason `no-slice` |
| Signed out | 🔴 **offered a draft form and a "Sign in to join"** | gated, reason `signed-out`, with sign-in as the notice's control |

**The removal: a signed-out visitor loses the Explore draft form.** That is deliberate, and
it is a consequence of D-09 rather than of this gate:

- `16-CONTEXT.md` settled that a signed-out visitor could draft, and that the draft survived
  sign-in — `migrateSignedOutDrafts` exists for exactly that. It worked because the only
  signed-out Explore was the **placeless** `geoid: null` composition, so the draft key
  carried no geoid and could be re-keyed onto whatever slice the member turned out to hold.
- **D-09 deletes the placeless Explore.** After 17-04 an observer looks at a *real named
  place* or at the welcome screen, never at a shell. A draft typed about Portland carries
  `city|4159000|…`, which `migrateSignedOutDrafts` correctly leaves alone (its rule: "a key
  with a non-null geoid is already bound") and which `canPostDraft` then refuses as `moved`.
  So the affordance's only possible outcome after D-09 is a dead end with text in it.
- 🔴 **`migrateSignedOutDrafts` stays, untouched.** Drafts already in a visitor's
  `localStorage` from before this ships must still re-key on sign-in. It becomes a no-op for
  new drafts, not dead code to delete. Same for `shouldResume` and `cs_explore_resume_v2`.

What replaces it is the honest version of the same invitation, and it is the sign-up pitch:
the notice says conversations belong to the people who live under that government, and that
an Empowered Vote account **with an address set** is what opens them. 🔴 Both halves — the
ROADMAP records that "Make an account" is not the whole instruction and will strand anyone
who stops there, because Civic Spaces needs the **Connected** tier and Connected means an
address has been set.
