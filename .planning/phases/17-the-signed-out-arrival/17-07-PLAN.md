**Goal:** Decide whether the phase is done, on evidence. Screenshots that were **looked
at**, contrast resolved the only way Tailwind v4 permits, every control hit-tested at both
viewports, the copy read out loud against the three decisions that constrain it, and the

through the arrival walk and writes PNGs. Then a human. 🔴 **A clean screenshot run only
proves the images decoded** — `16-VALIDATION.md` says so and Phase 16 found it to be true

judgement is the task.

**Tech Stack:** Playwright (**a global install — not in `node_modules`**) · Node 24 · no new
packages (see `17-SHARED.md`).

**Spec:** `CLAUDE.md` § "Design rules" in full; `17-CONTEXT.md` D-11, D-16, D-17, D-25;
`17-VALIDATION.md` (the verification bar, which this plan executes);

| # | Presentation |
|---|---|
| 1 | The welcome screen, signed out, nothing chosen |
| 2 | The picker open with results |

- [ ] **Step 2: 🔴 The theme, asserted and not assumed**

Set `ev_color_scheme` on the **browser context** and, before every shot, assert
`documentElement.classList.contains('dark')` equals what was asked for. **Playwright's
`colorScheme` option does nothing in this app**: `index.html` reads the cookie before first
paint and deliberately ignores `prefers-color-scheme`, testing `s !== 'light'` rather than
`s === 'dark'`. A run that does not assert this silently produces 24 dark shots and reports
a four-way pass.

Encode the asserted theme in the filename — `welcome-light-390.png` — so a mislabelled shot
is visible in the directory listing rather than only in the viewer.

- [ ] **Step 3: Playwright, the repo's way**

Resolve via `npm root -g`; import as `mod.chromium ?? mod.default?.chromium`. Copy
`loadChromium` from `check-explore-gate.mjs:98-118`. 🔴 It is a global install; searching
`node_modules` and concluding this repo has no headless browser is wrong, and the global
package's export shape differs between its CJS and ESM entry points.

- [ ] **Step 4: Run and commit the script, not the images**

```bash
npm run dev
npm run shoot:welcome
git add scripts/shoot-welcome.mjs package.json .gitignore
git commit -m "test(welcome): 24 shots across six presentations, two themes, two viewports

Theme set by the ev_color_scheme cookie and ASSERTED against documentElement.classList
before every shot, and encoded in the filename — Playwright's colorScheme option does
nothing here, so an unasserted run quietly produces 24 dark images and reports a four-way
pass. Output is gitignored, like banner-shots."
```

🔴 **This is the task. The script is its setup.** A clean run proves the PNGs decoded.

- [ ] **Step 1: Open all 24**

For each, ask the three questions that have actually gone wrong in this repo:

1. Does any text sit on a colour that only exists in one mode? A `dark:`-only colour reads
   fine in dark and vanishes in light.
2. Does anything overflow at 390px, or produce a horizontal scrollbar?
3. Does the welcome screen's primary action — the picker — sit above the fold on the phone?

- [ ] **Step 2: Read the copy out loud, against the three decisions that constrain it**

Not skim. Out loud, the whole welcome screen and both honest states.

| Decision | What would violate it |
|---|---|
| 🔴 **D-25 / Pitfall 11** | any implication that a post will be findable, searchable, indexed, or will unfurl in a link preview. There is no SSR, no prerender, no `robots.txt`, and one static set of `og:` tags — and even after Phase 18 the exposure is the **PostgREST endpoint**, not the pages |
| 🔴 **D-17 / D-02** | the words *anonymous* or *untraceable*, or any sentence that implies posting carries no consequence. The honest claim is **private from other members**; there is a paper trail, and it is how mis- and disinformation sources are identified |

### Task 3: Contrast through a canvas, and hit-tests at both viewports

**Files:**
- Modify: `scripts/shoot-welcome.mjs` — a `--audit` mode, or a sibling block in the same run

- [ ] **Step 1: 🔴 Contrast, resolved the only way that works**

Tailwind v4 emits `oklch()`. A probe that reads `getComputedStyle().color` and parses it as
`rgb()` reports confident nonsense.

And **setting `ctx.fillStyle` is not resolving it**: Chromium accepts `oklch()` and hands it
straight back, so a probe that reads `fillStyle` parses `0.446 0.03 256.802` as if it were
RGB and reports ~1:1 for perfectly legible text. 🔴 **You must `fillRect` and then
`getImageData` one pixel.**

A ratio near 1:1, or a whole page "failing", is this bug and not a finding. If you see it,
fix the probe before you touch a colour.

Probe, in both themes: the welcome screen's headline, body copy, help line and privacy
block; the picker's label, input text and option rows; the place strip's place name and
leave control; the honest conversations state. **4.5:1** for text, **3:1** for a meaningful
icon.

- [ ] **Step 2: Hit-test every primary control, at both viewports, in both themes**

`document.elementFromPoint()` at the centre of: the picker input, the first option row, the
welcome screen's sign-in link, the place strip's change and leave controls, and the
`ReadOnlyNotice` control on each reason that has one.

🔴 **Rendering is not reachability, and this failure is viewport-specific.** PR #92 shipped
a photo credit whose licence link sat under the content layer's `md:pb-7` padding at
`z-10` — a `z-index` that was correct while the credit was plain text, invisible to every
PNG and to `tsc -b`, and broken only at `md` and up, so phones looked fine.

When one fails, fix the layering and then 🔴 **toggle the suspect class off mid-run and
re-test.** A fix that is load-bearing puts the bug straight back. If removing it changes
nothing, you fixed something else and the real bug is still there.

- [ ] **Step 3: `prefers-reduced-motion`**

Run once with it on. Nothing on the welcome screen or in the picker should animate. 🔴
`motion` at this version does not **declare** `useReducedMotion` in its types, so the guard
has to be CSS or the animation has to not exist — `SeedInvitationModule` records this
decision and chose none.

- [ ] **Step 4: Commit the audit**

```bash
git add scripts/shoot-welcome.mjs
git commit -m "test(welcome): contrast through a canvas, hit-tests at both viewports

Contrast is resolved by fillRect + getImageData on one pixel. Reading ctx.fillStyle back is
NOT resolving it — Chromium returns the oklch() string and an rgb() parse of
'0.446 0.03 256.802' reports ~1:1 for legible text, so a whole page 'failing' is this bug,
not a finding. Hit-tests run at 1440 and 390 in both themes: PR #92's unclickable credit
link was md-and-up only, so phones looked fine and every screenshot passed."
```

### Task 4: The whole suite, in one run

- [ ] **Step 1: Everything, in order**

```bash
npm run build                 # tsc -b && vite build
npm run check:write-access    # pure, 18
npm run check:place-resolve   # pure, over committed fixtures
npm run check:composition     # pure, 62 — unchanged by this phase
npm run check:agenda-topics   # pure — unchanged by this phase

npm run dev                   # in another terminal, for the four below
npm run check:place-entry     # 13
npm run check:explore-gate    # six viewers
npm run check:explore-rooms   # unchanged by this phase

node scripts/check-place-resolve.mjs --live    # network: ev-accounts contract drift
npm run check:banners                          # network: 227 assets vs the manifest
```

🔴 **`check:banners` is in this list on purpose.** A visited place renders a hero banner from
Essentials' shared bucket, so this phase puts far more of those 227 assets in front of far
more people. A banner can change photographer with no diff on our side — Essentials swaps the
bytes behind a stable URL, so every build, every 404 check and `tsc -b` stay green while the
credit beside it becomes the wrong person's name. Attribution on a CC BY / CC BY-SA image is
a licence condition, and Treasury Tracker published a wrong photographer for three weeks this
way.

🔴 **`--live` is in this list on purpose too.** 17-05's browser check serves committed
fixtures; a stale fixture makes it green against an API that changed. The research's own
"valid until" note says ev-accounts' endpoint shapes move and that it was 14 commits ahead of
the local checkout on the day it was written.

- [ ] **Step 2: A SKIP is not a pass**

Any check that skipped must be reported by name with what it did not cover. That is
`16-VALIDATION.md`'s rule and this phase inherits it.

- [ ] **Step 3: Walk the verification bar by hand**

`17-VALIDATION.md`'s five lines are the phase's acceptance criteria. Walk each, signed in
and signed out, and record the answer:

1. A signed-out visitor gets the welcome screen, and never a placeless Explore.
2. Anyone can name a place and see its Explore, banner, officials and calendar — **including
   a place with no slice row**, which is the common case at 15 rows in the whole product.
3. No write is offered where a write cannot land: signed out, Inform-tier, another place, a
   sibling shard, a tab with no slice. Feed, thread **and** Explore.
4. The address is never stored, never echoed, never logged by us.
5. Light + dark, desktop + mobile all check out.

🔴 **Line 2's officials half is the one no script covers.** No automated check can tell one
real person's name from another's. Read the sidebar at a visited place, on City and on
Federal, confirm the names belong to **that** place, then leave and confirm they are the
member's own again. 17-06 Task 4 named this gap; this is where it is closed by a human.
