# Phase 17-06 — Officials, the sidebar and Explore for a visited place

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "Representing this community" names the community on screen, not the viewer's own.
Explore offers an observer nothing they cannot do. And `check:explore-gate` grows its last
two viewers, so every one of the four reasons a write can be refused is pinned by a browser
that watched it.

**Architecture:** `useRepresentatives(userId)` calls `/representatives/me` with a bearer and
**cannot** follow a place. `POST /essentials/browse/by-area` already can, anonymously, and
the dev path in that very hook has been using it for the dev id since Phase 11. So a sibling
hook returns the same `UseQueryResult<PoliticianFlatRecord[]>` shape, `AppShell` picks which
one to pass, and `Sidebar` / `SidebarMobile` change not at all. Then one guard in
`registry.tsx`, one `destination` that stops naming a place nobody can post to, and two more
viewer cases in the existing gate check.

**Tech Stack:** React 19 · TypeScript 5.7 · TanStack Query · Playwright (**a global install
— not in `node_modules`**) · no new packages (see `17-SHARED.md`).

**Spec:** `17-RESEARCH.md` **Q3.3** (the unseeded place is the common case, and the
`seed-invitation` guard), **Q3.4 item 4**, **Pitfall 9**, **Pitfall 2**; `17-CONTEXT.md`
D-07, D-10, D-11, D-20; `16-CONTEXT.md` locked decision 4 and locked decision 6 (seeding is
a vote).

**Depends on:** 17-05. **Execute serially after it.**
🔴 **This plan edits `scripts/check-explore-gate.mjs` and so did 17-02.** 17-02 added the
`signed-out` and `no-slice` viewers; 17-04 re-pointed the first at the welcome screen's place
view. This plan adds `other-place` and the observer-with-a-place. **Four viewers, one
script.**

**Carries:** D-07 (the Explore half), D-10, D-11, D-20; research Q3.3, Q3.4 item 4,
Pitfalls 2 and 9.

### Task 1: `usePlaceRepresentatives` — the officials of the place on screen

**Files:**
- Create: `src/hooks/usePlaceRepresentatives.ts`
- Modify: `src/components/AppShell.tsx` — `:544`, `:1239`, `:1364`
- Reference (do not edit): `src/hooks/useRepresentatives.ts` (`fetchDevRepresentatives` at
  `:15-27` is this request, already written and already anonymous),
  `src/lib/exploreComposition.ts` (`racesAreaFor`, the city-then-county ladder),
  `src/components/Sidebar.tsx` (`repsData: ReturnType<typeof useRepresentatives>`),
  `src/types/representatives.ts` (`filterRepsByTab`)

- [ ] **Step 1: 🔴 Pitfall 9, stated before anything is written**

*"**`useRepresentatives(userId)` silently following the viewed place.** What goes wrong:
your representatives render beside their conversations. Why: it is hoisted in `AppShell`,
keyed on the account, and its name does not say so."*

It cannot be made to follow a place even if you wanted it to: it calls
`GET /api/essentials/representatives/me` with a bearer, which 401s without one and answers
about the **account** with one. The substitute is in the same file, ten lines up:

```ts
POST `${EV_API_ORIGIN}/api/essentials/browse/by-area`  { geo_id, mtfcc }   // no auth
```

Anonymous, CORS-allowed for `civicspaces.empowered.vote`, and in use since Phase 11 to fetch
Asheville's real officials for the dev id. `src/lib/toolCoverage.ts` already carries the
request shape.

- [ ] **Step 2: The hook, shaped so the sidebar needs no change**

```ts
export function usePlaceRepresentatives(area: ElectionArea | null): UseQueryResult<PoliticianFlatRecord[]>
```

Same return type as `useRepresentatives`, because `Sidebar` and `SidebarMobile` declare
their prop as `ReturnType<typeof useRepresentatives>`. 🔴 Matching the shape is what makes
this plan a two-line change in two components instead of a prop refactor across four.

`enabled: !!area`, `staleTime` matching the sibling hook, `retry: 1`.

🔴 **No fixture fallback.** `useRepresentatives` falls back to `MOCK_REPRESENTATIVES` for a
synthetic user id, because the member-only endpoint 401s for the dev id and that is expected.
This endpoint is **public** and answers for the dev id exactly as it answers in production,
so a failure here is a real failure and must surface as one. `CLAUDE.md`'s rule: if a request
fails, say so and stop; do not swap in invented data.

- [ ] **Step 3: One area, the most local, and one request**

`racesAreaFor(onScreenSlices)` — city (`G4110`) else county (`G4020`), else `null`. 17-02's
`fetchDevRepresentatives` already walks this ladder; lift that logic here rather than writing
a second one.

One call is enough for every tab: the by-area response for a city returns the whole ladder —
the research measured 57 politician records for Asheville, federal included — and
`filterRepsByTab` already narrows per tab. That is how the dev path has always worked.

🔴 **Called once, in `AppShell`, beside `useRepresentatives`.** All five feed panels plus
Volunteer mount at once, so a hook inside one fires six times. Both hooks are called
unconditionally — rules of hooks — and only one fetches, because the other's `enabled` is
false.

- [ ] **Step 4: `AppShell` picks**

```ts
const ownReps = useRepresentatives(userId)
const placeReps = usePlaceRepresentatives(isVisitingPlace ? racesAreaFor(onScreenSlices) : null)
const repsData = isVisitingPlace ? placeReps : ownReps
```

🔴 **A place with neither a city nor a county geoid yields `null` and no request.** That is
federal or unified as the only level, which is not a place — `racesAreaFor` already answers
`null` rather than inventing a fallback, and its doc says why at length. The sidebar then
shows its existing no-representatives state, which is honest.

- [ ] **Step 5: The sidebar's other widgets, checked rather than assumed**

`Sidebar` takes `location`, `events` and `about` as ReactNode, built in `AppShell`. 17-04
moved `ActiveEventsWidget` and `ActiveAboutWidget` onto `onScreenSlices` and hid
`ActiveLocationCard` while visiting. **Confirm all three on screen** at a visited place:

- Events names the visited place and lists **its** elections and meetings.
- About names the visited place, with its 2020 population and its parent county and state.
- 🔴 The member's own "Showing content for {their place} · Change" is **not** on screen. Its
  Change link goes to the accounts app to edit **their** address; beside another city's feed
  it is an invitation to change the wrong thing.

- [ ] **Step 6: Build, look, commit**

```bash
npm run build
npm run dev   # ?dev=1, enter another place, read the sidebar on City and on Federal
git add src/hooks/usePlaceRepresentatives.ts src/components/AppShell.tsx
git commit -m "feat(place): officials for the place on screen, from the public by-area endpoint

useRepresentatives calls /representatives/me with a bearer and answers about the ACCOUNT —
Pitfall 9 is your representatives rendering beside their conversations. The substitute was
already in that file: POST /essentials/browse/by-area, anonymous, in use for the dev id
since Phase 11. Same return type, so Sidebar and SidebarMobile are unchanged. One request
for the most local area serves every tab, because the by-area response carries the whole
ladder and filterRepsByTab already narrows it. No fixture fallback: this endpoint is public
and a failure is a real failure."
```

### Task 2: Explore offers an observer nothing they cannot do

**Files:**
- Modify: `src/components/explore/registry.tsx` — `:318-322`
- Modify: `src/components/AppShell.tsx` — `ActiveExplore`'s `destination` (`:436-439`,
  `:456`)
- Reference (do not edit):
  `src/components/explore/modules/SeedInvitationModule.tsx:42-48` (the comment that
  explains why it does **not** read `isViewOnly`, which is still right and is exactly why
  this guard is needed instead)

- [ ] **Step 1: The `seed-invitation` guard**

Today: `available: (ctx) => ctx.composition.isUnseeded && !!ctx.placeName`. No authentication
term, no membership term.

🔴 **It invites a vote, and D-11 says an observer is never offered an action they cannot
take.** `16-CONTEXT.md` locked decision 6 made seeding a **vote**, and 16-08 shipped the
invitation *without* the vote — so the module is already an invitation to something that
does not yet count. Showing it to someone who could not vote even when it does is the same
failure one step further out.

Add `ctx.isAuthenticated && !ctx.isViewOnly` to the predicate. 🔴 Note the module's own
header is **still correct and must stay**: it deliberately does not read `ctx.isViewOnly`
inside its body, because its single control is navigation and gating that would make another
shard's Explore a dead page. The gate belongs in the registry's `available` — whether the
room opens at all — not in the module's rendering.

- [ ] **Step 1b: 🔴 `check-explore-rooms.mjs` names the old predicate in its failure text**

`scripts/check-explore-rooms.mjs:471-476` asserts *"the seed invitation renders on an
unseeded place"*, and its failure detail reads: *"…that the registry entry's `available()`
is `isUnseeded && !!placeName` and not the inverted 16-06 guard."*

The **assertion** stays green — it runs `?dev=1`, an authenticated dev guest on their own
shard, so both new terms are true. The **failure text** goes stale the moment Step 1 lands,
and it is the first thing someone reads when that assertion ever does fail. Send them to a
predicate that no longer exists and they will look for the wrong bug.

Update that detail string to name all four terms, and add one line saying that the two new
ones are checked by `check:explore-gate` viewers 5 and 6 — so the two scripts point at each
other rather than each half-describing one rule.

Then run it and confirm green **before** moving on:

```bash
npm run check:explore-rooms
```

If it goes red, the dev guest is failing one of the new terms, and that is a finding about
Task 1 — not a reason to relax the assertion.

- [ ] **Step 2: Sweep the rest of the registry for the same shape**

Walk every entry's `available` and its component, and answer one question each: *does this
offer an action that a visitor, or a member looking at another place, cannot take?*

- Navigation (`openTopic`, `What's new`, every `sourceUrl` link) is fine — RLS has no opinion
  about a link, and gating it would reduce another place's Explore to a dead page, which
  fails the goal from the other direction. `check:explore-gate` assertion 8 exists to catch
  over-gating and must stay green.
- Device-local preferences (`cs_saved_adventures`, `cs_explore_ui`) are fine: they never
  touch Supabase, and `16-CONTEXT.md` settled that they are not writes.
- Anything that *offers* a Supabase write is already gated on `isViewOnly`, which now carries
  all four reasons (17-02).

Write the sweep's verdict into the commit body — which entries you checked and why each is
fine. 🔴 "I looked" is not a record; `17-RESEARCH.md` Finding 5's table of ten affordances is
in the repo precisely because an unwritten sweep gets re-done wrongly.

- [ ] **Step 3: `destination` is null while visiting**

`ActiveExplore` builds `destination` from `activeSlice` (`:436-439`), which while visiting is
a place slice carrying a `place:` sentinel id. Every write is already gated, so no draft key
is built from it today — but the value is wrong and the next reader cannot tell it is
unreachable.

Pass `destination={isVisitingPlace ? null : destination}`. `ExploreView` already accepts
`null` — its doc says *"null when signed out, or when the member has no local community"* —
and now also when the community on screen is not theirs. Update that doc line.

- [ ] **Step 4: Build and commit**

```bash
npm run build
npm run check:composition
npm run check:explore-rooms
git add src/components/explore/registry.tsx src/components/AppShell.tsx scripts/check-explore-rooms.mjs
git commit -m "fix(explore): the seed invitation does not open for someone who could not seed

Its available() was isUnseeded && placeName, with no authentication term — so an observer
was invited to a vote that 16-08 has not built and that they could not cast if it had. The
module's own header stays as it is: it deliberately does not read isViewOnly inside its
body, because its one control is navigation and gating that makes another shard's Explore a
dead page. The gate belongs in the registry's available(), not in the rendering. Explore's
destination is null while visiting: every write is gated already, but a destination built
from a place: sentinel is a wrong value that reads as a live one."
```

### Task 3: `check:explore-gate` grows its last two viewers

**Files:**
- Modify: `scripts/check-explore-gate.mjs`
- Reference (do not edit): the viewer axis added by 17-02; `scripts/check-place-entry.mjs`
  (17-05) for how to reach a place in the browser

🔴 **Extend. Four viewers, one script.** `17-RESEARCH.md` Pitfall 2 is "shipping half the
gate, again", and its avoidance note is explicit: add the new viewers as **cases of the same
check**, keep the control case, and keep reading *which* case failed.

- [ ] **Step 1: Viewer 5 — `member-other-place`, signed in, visiting**

Boot `?dev=1`, enter a place through the strip (the same route-interception fixtures 17-05
uses — import them, do not re-capture), and then:

**The control case first, and it is strong here**: on the member's **own** feed before the
trip, the topic form's title input, "Your thoughts" textarea and submit are present, and on
City so are the Imagine textarea and "Share an idea" — 🔴 the Imagine controls are inside
`{option && …}` with a persisted default of `null`, so **click a radio first**; without it
the control case fails on the first run in a perfectly ungated build. That click is the
existing script's and must be reused, not re-derived.

Then, at the visited place, on the **list view and inside an opened topic**:

- zero `button[type="submit"]`
- zero `textarea`
- zero free-text `input` (radios and checkboxes excluded — they are view preferences)
- no write wording (`WRITE_WORDS`, unchanged)
- the read-only notice is present and names the **other-place** reason
- 🔴 the `seed-invitation` module is **absent**, even on an unseeded place where it would
  otherwise be the second module in the list. This is Task 1's assertion and it has to be
  made on a place that is genuinely unseeded — which, at 15 slice rows in the entire
  product, is any place the fixture names

- [ ] **Step 2: Viewer 6 — `observer-with-a-place`, signed out, visiting**

`?signedout=1`, then a place. The same absence assertions, with the notice naming the
**signed-out** reason and offering sign-in.

🔴 **The control case for this viewer is inverted and must be stated as such** — 17-02 Step 2
established the pattern and the same two things make it non-vacuous:

1. The Explore panel rendered a **non-empty** `[data-explore-module]` list for a real geoid.
2. The notice is present and carries a control.

🔴 **And one more, because this viewer is the one whose absences are cheapest to fake:**
assert the hero banner **names the place**. A run where the place never loaded has no
textareas either.

- [ ] **Step 3: Not over-gated, for both new viewers**

Assertion 8's job, applied here: at a visited place the device-local controls must still
work — the Nearby dialog opens and "Save on this device" toggles both ways, the Imagine
radios still select, topics still open. 🔴 A failure here is **over**-gating: another place's
Explore reduced to a dead page, which fails D-18 from the other direction. `17-CONTEXT.md`
settled that device-local preferences that never touch Supabase are not writes.

(City and County only, by composition. If the fixture place has no city, say **SKIP** and
name what was not checked — a SKIP is not a pass.)

- [ ] **Step 4: Errors, per viewer**

Reuse `EXPECTED_NOISE`; print the suppressed lines. 🔴 A signed-out boot and a visiting boot
produce **different** noise from the dev id's — with no `cs_token` the member-only endpoints
are not called at all, so some allowlisted 401s simply never appear. An allowlist entry that
never matches is fine; an unexpected error is not. A thrown render is not a gate: an
exception while hiding a control can leave the control on screen.

## Out of Scope

- **Reading a visited place's conversations.** Phase 18. The honest state stands.
- **Any migration, grant or policy.**
- **The seed vote.** `16-CONTEXT.md` locked decision 6: seeding is a vote, the invitation
  ships without it, and the vote waits for a real write path. This plan only stops the
  invitation opening for someone who could not cast one.
- **Gating navigation, `cs_saved_adventures` or `cs_explore_ui`.** Device-local preferences
  that never touch Supabase are not writes; removing them makes another place's Explore a
  dead page.
- **The suspended-member and `inform`-tier gates** in `SliceFeedPanel.handleCompose`.
  Unchanged, and settled out of scope.
- **`useCompassData` following a place.** Permanently out of scope: ranking is about the
  reader, and locked decision 7 says no slice-wide aggregate of members' political answers is
  computed, stored, requested or designed.
- **The four-way visual pass** on the sidebar at a visited place. 17-07.
- Adding a frontend test framework.
